# 성정원통사의원 환자 안내 화면

성정원통사의원 환자용 주소는 보담의 기존 키오스크 화면과 상태 제어를 사용합니다. 시작하기 → 실손보험 세대 → 보험사 형태 → 치료 원인 → 치료 선택 → 세 금액 카드 순서입니다. 세대 확인 안내는 1단계에서, 계산 근거와 서류 확인은 정상 결과 화면에서 열립니다. 환자 식별 정보 입력 없이 계산하며 선택과 입력 금액은 서버로 보내거나 브라우저 저장소에 남기지 않습니다.

웹에서는 PC의 좌우 여백과 두 열 배치, 태블릿 세로의 한 열 배치, 좁은 화면의 세로 금액 카드를 사용합니다. 목록과 도움말은 페이지 한 곳에서 스크롤하며 하단 조작은 콘텐츠 바로 다음에 있습니다. 기존 전체 화면 키오스크에 이 스타일을 적용하지 않습니다.

## 예상 부담액의 근거와 범위

2026-11-23에 공개 자료를 확인했습니다.

- [병원 공식 비급여 가격표](https://www.tongsaclinic.com/sub/unpaid.php): 체외충격파 한 부위 100,000원, 프롤로 주사 한 부위 50,000~100,000원. 체외충격파는 공시 금액이 실제 치료비와 같은 경우, 프롤로 주사는 병원이 확인한 금액을 공시 범위 안에서 입력한 경우에만 계산합니다.
- [심평원 행위 비급여 목록](https://www.hira.or.kr/ebooksc/2026/03/BZ202603053039374.pdf): 체외충격파치료(근골격계질환) SZ084, 증식치료(사지관절·척추) MY142/MY143. 실제 청구 코드는 진료비 세부내역서나 원무과에서 확인합니다.

약관 원문 링크, 조항, 공제액, 한도, 보상 단위는 [등록 SQL](data/insurance-rules.sql)에 보관합니다. 공제 기준은 등록한 **해당 상품과 담보**에만 적용합니다.

| 구분 | 등록 약관 | 의원 비급여 1건 공제 |
| --- | --- | --- |
| 1세대 | LIG 웰빙보험 2008.10, 질병통원의료비Ⅲ(30만원한도) | 건강보험 적용 시 통원 1일 5,000원. 참고용, 화면 산출 제외 |
| C1 | 삼성화재 Super V(s1004), 갱신형 실손 외래 담보 | 방문당 10,000원 |
| C2 | 삼성화재 실손의료비보험(1509.5) 2종(선택형Ⅱ) 외래 | 10,000원과 보상대상 비급여의 20% 중 큰 금액 |
| C3 | KB개인실손의료비보험 2017.04, 도수·체외충격파·증식치료 특약 | 20,000원과 30% 중 큰 금액 |
| C4 | KB손해보험 실손의료비보장보험(23.01), 3대 비급여 특약 | 30,000원과 30% 중 큰 금액 |

C1·C2는 이번 외래의 실손 보상 대상 비용이 선택한 치료비뿐이고 환자가 외래 가입금액 및 남은 횟수를 확인했을 때만 계산합니다. C3·C4는 선택한 한 부위 치료가 한 건으로 청구되고 특약 보상 횟수와 한도가 충분해야 합니다. C4는 합산 첫 10회 이내만 지원합니다. 모두 정확한 유효 약관, 실제 청구 코드·금액, 해당 치료 보장 여부를 확인해야 합니다. 치료 원인 또는 보장 조건을 모르거나, 상품이 다르거나, 한도가 부족하면 보험금과 보험금 수령 후 본인 부담은 산출하지 않습니다. 진찰료·검사료·다른 치료나 SNEPI는 포함하지 않습니다. 5세대, 생명보험·공제조합 등 미등록 조건도 계산하지 않습니다.

## 실행 및 게시

화면 회귀 시험은 Chromium을 설치한 뒤 `npx playwright test -c patient-kiosk/playwright.config.ts`로 실행합니다. PC, 작은 노트북, 태블릿 세로·가로, 좁은 분할 화면과 큰 글자 보기에서 네 단계·결과·근거·서류 안내를 확인합니다.

저장소 루트에서 `npm ci`, `npm run build:patient-kiosk`, `python -m http.server 3419 --bind 127.0.0.1 --directory dist-ssr/patient-kiosk`를 실행하고 `http://127.0.0.1:3419/`를 엽니다. 계산 시험: `npx vitest run tests/patient-kiosk`.

보험 기준만 등록하려면 Node 24에서 `npm run patient:rules:register`를 실행합니다. 이 명령은 버전 관리하는 SQL로 `dist-ssr/patient-insurance-rules.sqlite`를 다시 만들고, 그중 계산에 쓸 수 있는 기록이 저장소의 배포용 JSON과 일치하는지 확인합니다. SQL을 변경한 경우 `npm run patient:rules:register -- --write-snapshot`으로 스냅샷을 다시 만들고 SQL과 함께 검토합니다. 빌드에서도 같은 확인을 실행합니다. SQLite 파일은 정적 게시 경로 밖에 있으며 이 화면에서 환자 데이터나 관리자 입력을 SQLite에 기록하지 않습니다.

Render: 기존 `bodam-seongjeongwon-patient-kiosk` Static Site의 게시 경로는 `dist-ssr/patient-kiosk`입니다. 배포 빌드는 별도의 관리자·운영·베타 서버, API 또는 합성 카탈로그를 참조하지 않습니다. 공개 주소에서 세 단계와 치료 선택을 거쳐 정상 결과와 보류 결과, 계산 근거, 서류 안내와 결과 복귀를 확인합니다. `PUBLIC_REFERENCE`는 가격표와 약관을 결합한 정적 배포 내부 출처로 서버 규칙 승인과는 별개입니다.
