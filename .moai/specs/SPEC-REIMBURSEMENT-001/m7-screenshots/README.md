- `bundle-run-log.txt` 는 이 단계의 확인 명령(tsc·단위 시험·빌드·브라우저 시험 프로젝트들)의 출력 꼬리와 종료 코드, 흐름 시험이 관찰한 BEFORE/AFTER 응답 발췌, 거절 시험이 관찰한 응답(상태 + 사유)이다. 전체 단위 시험의 실패 2건(`request-static`)은 이 작업 폴더의 CRLF 줄바꿈 때문이며 이 단계와 무관하다.
- 게시 확인값(미리보기 우회 방지 보강): 확인값은 서버가 깨끗한 미리보기를 만들 때 발급해 서버에 기록해 두는 예측할 수 없는 일회용 값이다. 입력에서 다시 계산할 수 있는 값이 아니므로 미리보기를 한 번도 받지 않은 검토 담당자는 게시할 수 없고(409 PREVIEW_REQUIRED), 다른 관리자가 받은 값·다른 구성의 값·미리보기 뒤 구성이 바뀐 값·이미 쓰인 값도 같은 409 다. 기록은 "서버가 이 관리자에게 이 구성의 미리보기를 만들었다"는 증거일 뿐 사람이 화면을 읽었다는 증명이 아니다. 그래서 `bundle-run-log.txt` 의 저장소 사본 비교에는 새 영역 `bundleConfirmations`(미리보기마다 한 건, 게시가 한 건을 소비)가 들어 있고, 화면 미리보기 직후에는 이 영역만 달라진다. 사진 열다섯 장은 이 보강 이전 실행에서 만든 것이며 보강은 화면 모양을 바꾸지 않았으므로 다시 만들지 않았다(바뀐 사진 없음).
- 직접 열어 본 사진: 위 열다섯 장 전부(`bundle-1` ~ `bundle-12`). 사진을 열어 본 뒤 고친 것: 기준 묶음 표의 머리글 "기준"과 알약 "사용 가능"이 두 줄로 쪼개지던 것, 규칙 사용 범위 표의 병원 이름·적용 문장 칸이 글자 중간에서 끊기던 것, 시험 자료 항목의 버전 "v1" 앞에 "v" 가 한 번 더 붙어 "vv1" 로 보이던 것. 남은 모양 문제: 후보 표의 승인자 칸이 긴 시험 계정 id 를 글자 중간에서 줄바꿈한다(실제 계정 id 는 더 짧을 것으로 보이며 확인하지 않았다).
- 로컬에서 직접 해 보기: `npm run preview:bundle`(빌드 후) 또는 `npm run preview:bundle:run`. 계정별 순서가 출력된다(`tests/e2e/harness/preview.ts`). 기본 미리보기(`npm run preview:kiosk`)는 그대로이고 묶음 시연 세계는 켜야 열린다.
- 한계: 운영 인증·실제 병원 자료는 이 단계에 없다. 게시된 묶음을 나중에 중지하는 화면(중지 묶음의 기준 선택 불가·지정 불가 표시)과 승인 뒤 치료 정보가 바뀐 경우의 서버 거절 외의 결함 코드(유효 기간 밖 등)의 **화면**은 이 시험이 만들지 않았다(문장은 단위 시험이, 서버 동작은 서비스·API 시험이 본다).
