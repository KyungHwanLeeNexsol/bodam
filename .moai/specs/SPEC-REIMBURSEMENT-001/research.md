## 2. 뽑은 사실 (출처별)

### 2.1 제품 범위와 입력 흐름
- 입력은 ①실손 세대 ②보험사 형태 ③치료 원인 ④치료의 네 단계이며, 대기/시작 화면은 단계에 넣지 않는다(기획서 13행, 63-71행).
- 세대 카드는 1세대(A·S), 2세대(C1), 2.5세대(C2), 3세대(C3), 4세대(C4) 다섯 장이며 C1과 C2는 따로 고른다(기획서 5행, 33행, 77행). 5세대·중증/비중증·특약1/2·건보 본인부담률 연동은 제외한다(기획서 5행, 523행).
- 기간 경계는 반개구간이다(기획서 55행).
- 세대를 모르면 가입일 확인 안내와 1544-8069 문구만 보여 주고 화면 1로 돌아간다. 치료비 합계만 보는 경로는 없다(기획서 78-81행).
- "1588"은 전체 번호가 아니므로 표시하지 않는다(기획서 83행). 1544-8069는 문구로만 둔다(기획서 83-85행, 176행).
- 보험사 형태는 손해보험사·생명보험사·그외 공제 조합 세 장이고, 이름 목록·검색·추가 질문이 없다(기획서 90-92행).
- 공제·한도·특약은 묻지 않고 세대·보험사 형태별 표준 가정 프로필로 계산한다(기획서 94-96행).
- 치료 원인은 서류 안내에만 쓰고 금액 계산에는 넣지 않는다. "잘 모르겠어요"는 보류 사유가 아니다(기획서 111행, 118-125행).
- 치료 목록은 페이지로 넘기며 선택을 유지하고, 같은 항목 중복 클릭은 한 번으로 친다(기획서 127-137행).

### 2.2 계산 기준과 결과 상태
- 결과는 "입력으로 확인한 것 / 확인하지 않은 것 / 가정으로 적용한 것 / 계산하지 않는 것"을 섞지 않는다(기획서 98-114행).
- 승인된 표준 가정 프로필과 승인된 치료 보장 매핑이 모두 있어야 예시 계산을 한다. 없거나 초안·DEMO·미승인·무효·재검토 중이면 해당 치료가 보류되고, 하나라도 보류가 있으면 전체 예상 보험금과 수령 후 부담도 보류한다(기획서 109-110행).
- 미확정 표준값을 추정·대체·0원·전액 보장으로 채우지 않는다(기획서 113행).
- 결과 상태별 0원 처리: 미확인 null, 통신 오류 null, 확인된 제외 해당 항목 0원+사유, 정상 계산 0원은 근거와 함께 0원(기획서 158-167행, 273행).
- 보류(조건 미확인) 결과 화면은 디자인에 없으며 구현 설계 때 정한다(기획서 169행, 498행).
- 가정 문구 "선택한 치료가 모두 보장 대상이고 한도가 남아 있다고 가정"은 모든 치료가 보장 대상으로 확인된 경우에만 쓴다(기획서 171행).
- 세 금액 이름과 세 번째 카드 보조 설명은 고정이다(기획서 148-156행).
- 결과 문구 원칙과 공통 안내 문구는 고정 문장이다(기획서 190-200행).

### 2.3 계산 엔진
- 변수 T, G, N, E, X, U, D, L(기획서 255-262행)과 계산 순서 8단계(기획서 277-286행).
- 일반 그룹식 `P = min(max(E - D, 0), L)`, 수령 후 부담 `T - sum(P)`(기획서 290-292행). 모든 계약에 강제하지 않으며, L이 지급액 한도인지 보장 대상 비용 한도인지 명시해야 한다(기획서 294행).
- 공제는 치료마다 반복하지 않고, 서로 다른 담보의 공제를 하나로 합치지 않는다(기획서 296행).
- 대표 규칙 템플릿(기획서 302-313행): 2세대 전기 고정 D=10,000원, 2세대 정률 D=max(10,000원, 비율×E), 2세대 후기 표준형 D=max(10,000원, 0.20×(G+N)), 선택형Ⅱ D=max(10,000원, 0.10×G+0.20×N), 4세대 급여 D=min(G, max(10,000원, 0.20×G)), 4세대 일반 비급여 D=min(N, max(30,000원, 0.30×N)). 이 값들은 "설계·테스트 템플릿"이며 운영 약관이 아니다(기획서 300행).
- 금액은 원 단위 정수, 비율은 정수 분수 또는 basis points, 절사/반올림은 규칙마다 명시한다(기획서 315행).
- 예시 A-E(기획서 319-335행), 별도 한도 예시 400,000원(기획서 337행).
- 공통 불변 조건(기획서 471행).
- 보험금 계산은 독립적인 결정적 함수와 규칙 데이터로 설계하고 LLM의 판단에 의존하지 않는다(기획서 §12 원칙 10, 525행). 계산과 보상 설명에 생성형 AI를 쓰지 않는다(기획서 11행, 407행).

### 2.4 데이터·권한·API
- 역할은 병원 관리자, 보험 기준 검토 담당자, 플랫폼 운영자이며, 한 사람이 여러 역할을 맡아도 권한은 분리한다(기획서 372행).
- 규칙 관리 업무는 여섯 가지다. 4번(규칙의 초안→승인(검토 완료)→게시→중지 이력 관리)의 단계 전환은 보험 기준 검토 담당자의 권한이고, 5번은 계산 예제와 실제 약관을 대조한 승인 기록, 6번(병원별 관리자 권한과 규칙 사용 범위 관리)은 플랫폼 운영자의 몫이다. 1·2·3·5번을 검토 담당자와 플랫폼 운영자 가운데 누가 맡는지는 원문이 나누지 않았다(기획서 363-370행, plan.md §E #30).
- 병원은 가격·메뉴만 바꾸고 공제·한도는 못 바꾼다. 병원 관리자에게 "검토 완료" 선택지를 주지 않는다(기획서 350행).
- 보장 판단에 영향을 주는 변경은 승인된 매핑을 무효로 하고 재검토한다. 가격만 바꾸면 매핑은 유지하고 새 가격 버전을 게시한다(기획서 352-355행).
- 규칙은 삭제·덮어쓰기 대신 새 버전을 발행한다(기획서 374행). 계산 시점에 서버가 버전을 확인한다(기획서 376행).
- 데이터 엔티티 목록(기획서 382-393행). 표준 가정 프로필을 별도 엔티티로 둘지는 SPEC에서 정한다(기획서 395행).
- 세션은 메모리에만 두고 localStorage·IndexedDB·서비스워커 캐시·URL 쿼리·분석 이벤트에 남기지 않는다(기획서 397행).
- 예상 API 세 가지와 관리자 API(기획서 399-405행). 서버는 클라이언트의 단가·공제율·병원 ID를 믿지 않으며, 미리보기와 최종 계산은 같은 엔진을 쓴다(기획서 407행).

### 2.5 키오스크 표시·세션
- 임시 검토 화면 1080×1920 / 1920×1080, 조작 규격(버튼 88, 터치 72 CSS px, 카드 120, 본문 24, 제목 36, 결과 숫자 56, 간격 16)(기획서 562-576행).

- 큰 글자 보기는 전용 화면 없이 반응형으로 확대한다(기획서 580-590행).
- 무조작 시간: 입력 100/120초, 결과·계산 근거·필요 서류 160/180초(기획서 607-613행). 안내·오류·계산 중 화면의 무조작 처리는 구현 설계에서 정한다(기획서 613행).
- 이용 완료·처음으로·무조작 초기화의 도착지(기획서 619-625행). "잠시 후"의 길이는 정하지 않았다(기획서 622행).

- 검증 3단계(파일 확인 / 렌더링 확인 / 앱 동작 검증)와 디자인 파일로 확인할 수 없는 항목(기획서 641-649행). 이 3단계는 기획서의 분류다. acceptance.md가 쓰는 다섯 가지 표시(unit / integration / e2e-app / render / real-device)는 이 SPEC이 정한 자동 시험 분류이며, 기획서 3단계에 대응시킨 표는 spec.md §2에 있다.
- 지원 범위 밖 계약은 일반 개인 실손 규칙으로 계산하지 않는다(기획서 17행, 59행). 그런 계약을 가려내는 방법은 현재 디자인에 없다(기획서 494행).

## 3. 확정된 규칙과 미확정 자료

### 3.1 확정된 규칙 (문서에 고정되어 SPEC이 그대로 따르는 것)
1. 입력 네 단계와 각 단계 카드 구성, "다음" 비활성 규칙(기획서 75-123행).
2. 세 금액 이름·순서·세 번째 카드 보조 설명(기획서 148-156행).
3. 계산 가능/보류의 판정 조건과 0원 처리 규칙(기획서 98-114행, 158-167행).
4. 공제 후 한도 적용 순서, 공제 1회, 제외 비용의 공제 기준 배제(기획서 277-296행).
5. 결과 화면 여섯 동작과 복귀 규칙(기획서 142-145행, 216행).
6. 필요 서류 9줄 구성과 영수증·세부내역서 한 줄 항상 체크(기획서 209-212행). 원인을 모르면 상해만, 질병만의 두 조건을 각각 평가한다. 원인 모름의 7+1+1 분할은 확정 규칙이 아니라 **디자인 예시**다: 저장된 디자인(`K07_Documents_Unknown`)의 9줄 예시로, 공통 7줄과 상해 전용 초진기록지 1줄, 질병 전용 진단서 1줄이다. 이 예시는 합계 9줄이고 영수증·세부내역서 줄은 하나로 합쳐 항상 필요하다. 공통·상해 전용·질병 전용 줄의 실제 개수는 서류 규칙의 평가에서 나오며 상한이 없다(design.md DD-06). 실제 서류 요건은 아직 없다(보류-06, 기획서 215행). 원문 문장의 정정은 plan.md §H H-1~H-5가 소유자에게 넘긴다.
7. 무조작 시간 값(잠정이라고 명시된 기본값)과 이용 완료 동선(기획서 607-625행).
8. 권한 분리, 재검토 기준, 버전 발행 원칙(기획서 341-376행).
9. 세션 보호 규칙(기획서 397행, 617행).
